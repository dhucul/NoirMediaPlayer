# NOIR Media Player

NOIR is a modern, keyboard-first DVD, video, audio, and network-stream player for Windows. It is built with WPF on .NET 10, uses Windows Media Foundation for supported local and direct HTTP/HTTPS playback, and retains VLC/AACS as a compatibility fallback during the migration to Windows APIs.

## What is included

- Sleek black custom-chrome interface using Segoe UI Variable and Segoe Fluent Icons
- Windows Media Foundation playback with a LibVLC 3 compatibility fallback and hardware-decoding support
- Local video and audio playback across common container and codec formats
- Optical DVD and Blu-ray source discovery
- One-click optical-disc eject with active-drive selection
- `VIDEO_TS` and `BDMV` folder playback
- DVD menu activation and `Alt` + arrow-key navigation
- HTTP, HTTPS, RTSP, RTP, UDP, and direct network streams
- Multi-select file opening, recursive folder scanning, and drag-and-drop
- Searchable play queue with M3U/M3U8 import and export
- Shuffle plus Off, All, and One repeat modes
- Automatic next-item playback
- Remembered playback positions and recent-source history
- Audio-track and subtitle-track selection
- External SRT, ASS, SSA, SUB, VTT/WEBVTT, and IDX subtitle loading
- Playback rates from 0.5× to 2×
- Original aspect-ratio playback (Inspector → View → Aspect ratio → Original), optional ratio overrides, 90-degree rotation, and chapter navigation
- PNG video snapshots saved to `Pictures\Noir Snapshots`
- Fullscreen and always-on-top mini-player modes
- Persistent volume, mute, playback, and decoding preferences
- Per-monitor DPI awareness and long-path support

## Windows playback migration

**Quick Settings → Prefer Windows playback** is enabled by default and applies the next time a source opens. Windows Media Foundation is tried for local MP4, M4V, MOV, AVI, WMV, MP3, M4A, AAC, WAV, WMA, 3GP, ASF, FLAC, and MKV files. Direct HTTP/HTTPS URLs with these file extensions can also use native playback; Matroska requires successful bounded timeline inspection first and retains the compatibility cases described below. Playback uses the codecs available to Windows; a container extension does not guarantee codec support. A native startup failure, rendering error, or startup timeout automatically retries the source with VLC.

Turning off hardware decoding now keeps supported video and audio on Windows, including supported HTTP/HTTPS sources. Video uses Media Foundation's [frame-server mode](https://learn.microsoft.com/en-us/windows/win32/api/mfmediaengine/nf-mfmediaengine-imfmediaengineclassfactory-createinstance) without a [DXGI device manager](https://learn.microsoft.com/en-us/windows/win32/medfound/mf-media-engine-dxgi-manager), which selects software decoding and processing. Windows transfers each available frame into a WIC bitmap, and first-party Win32/GDI code presents it in the existing video window. Audio and the playback clock remain on Media Engine. Original proportions, all five aspect overrides, source orientation/PAR, manual rotation, resize modes, source-resolution captures, supported external captions and chapters, audio selection/off, pause/rate, restart, and later compatibility handoff retain their existing behavior. A single retained picture avoids frame or dispatcher queues; the WIC frame and display DIB are each limited to 64 MiB. Unsupported codecs, media-type negotiation, oversized surfaces, and presentation failures retry VLC. The current Windows software MJPEG fixtures in AVI and Matroska return `MF_E_TRANSFORM_TYPE_NOT_SET` and retain their working compatibility picture and captions. Unsupported embedded captions, alternate video, and other unknown streams still use compatibility playback. Disabling the Windows-playback preference selects VLC directly.

Plain embedded UTF-8/SRT subtitles in local MKV with ordinary default-track flags now use Windows [Media Foundation timed text](https://learn.microsoft.com/en-us/windows/win32/api/mfmediaengine/nn-mfmediaengine-imftimedtext) and its [cue notifications](https://learn.microsoft.com/en-us/windows/win32/api/mfmediaengine/nn-mfmediaengine-imftimedtextnotify), rendered by the first-party WPF caption presenter. Track names/languages, multiple embedded tracks, subtitles off, external-caption selection, paused seeking, replay and source-frame PNG captures retain their selections and timing. Initial selection occurs before playback starts so the first cue is included. Captions remain upright and follow the displayed picture during resizing. Windows cue data is copied into bounded managed text; native cue pointers are not retained. Formatted or positioned text, binary/image captions, overlapping cues, customized default/forced/accessibility track flags, other embedded formats and network captions retain VLC. A bounded first-party EBML metadata check preserves those automatic track choices without reading media payloads. A later unsupported cue switches to compatibility playback with position, pause, audio and subtitle choices restored; no embedded subtitle extraction or third-party parser is used.

Multiple audio tracks, track selection, and disabling/re-enabling audio now stay on the Windows backend. Track labels use the stream's name and language when supplied. Local video snapshots use a separate Media Foundation Source Reader to decode the frame at the playback clock, then save a PNG through Windows imaging without restarting playback or capturing the player controls.

Native snapshots also honor standard 0°, 90°, 180°, and 270° source orientation metadata, including portrait phone recordings. Media Foundation supplies the [stored frame rotation](https://learn.microsoft.com/en-us/windows/win32/medfound/mf-mt-video-rotation), and WPF applies the correction after pixel-aspect scaling and before composing captions. This keeps exported dimensions consistent with the native picture and captions upright, including local and supported HTTP video, anamorphic sources, and captures after resize, mini-player, or fullscreen changes. Unknown rotation attribute values, inconsistent decoder orientation, and decoding failures retain compatibility capture.

The manual Rotate control now keeps supported video on Windows. With hardware decoding enabled, Media Foundation presents through its [windowless swap chain](https://learn.microsoft.com/en-us/windows/win32/api/mfmediaengine/nf-mfmediaengine-imfmediaengineex-enablewindowlessswapchainmode), and first-party C# calls to Direct3D 11 and DirectComposition rotate the video surface by 90°, 180°, or 270° without reopening the media. With hardware decoding disabled, the GDI presenter applies the same rotation to software-decoded frames. Source orientation and pixel-aspect correction happen before manual rotation; the picture stays centered and letterboxed at its resulting original proportions through resizing, mini-player, fullscreen, and minimize/restore. External captions remain upright in the rotated picture, including native PNG captures. Rotation retains pause/play state, the clock, chapters, rate, audio off/selection, and caption selection. Restart also opens the selected rotation natively. Audio-only sources retain their transport and caption pane. If the graphics adapter cannot supply a composition device with hardware decoding enabled, the established Windows window renderer remains available for original presentation; unavailable or failed native rotation uses the existing VLC handoff.

The 16:9, 16:10, 4:3, 1:1, and 21:9 aspect overrides also stay on Windows. Media Foundation fills a surface at the source's exact display aspect ratio, and the software GDI presenter or [DirectComposition's visual transform](https://learn.microsoft.com/en-us/windows/win32/api/dcomp/nf-dcomp-idcompositionvisual-settransform(constd2d_matrix_3x2_f_)) fits the whole picture to the selected final ratio, including after manual rotation. No source pixels are cropped. The picture stays centered through resizing, mini-player, fullscreen, and minimize/restore; selecting Original restores source proportions. Caption layout follows the displayed picture while glyphs remain upright and unstretched. Pause/play state, the clock, audio off/selection, chapters, and the player instance are retained. Preselected ratios, changes while a source is opening, and restart also stay native. Audio-only sources keep the full caption pane. PNG exports retain source dimensions with pixel-aspect/source-orientation correction and manual rotation; ratio overrides affect the view, matching the existing compatibility capture behavior. Unsupported ratio strings, unavailable native presentation, excessive surface dimensions, and presentation failures retain VLC. A later unsupported feature carries the selected ratio and rotation through the existing handoff; VLC's existing paused H.264 input-clock reporting is unchanged.

Snapshots from supported finite, seekable HTTP/HTTPS video can also stay native when the server supplies consistent byte ranges. A read-only first-party .NET range stream feeds the [Windows Media Foundation byte-stream reader](https://learn.microsoft.com/en-us/windows/win32/api/mfreadwrite/nf-mfreadwrite-mfcreatesourcereaderfrombytestream); it uses a shared eight-second network deadline, at most 256 requests/64 MiB of input, and a 1 MiB cache. It checks range offsets, lengths, content encoding, and supplied entity validators before decoding. Media is read into bounded memory without saving a temporary video file. Captures use source resolution, pixel-aspect correction, and the selected supported external captions while retaining the playing/paused session, clock, playback rate, and audio selection. Servers without usable ranges, changed or incomplete responses, stalled reads, unsupported decoding, and other unmigrated snapshot cases retry through VLC with the existing session handoff.

The video surface is now a first-party Win32/WPF host shared by Windows playback and the VLC fallback. Its owned, non-activating overlay follows resizing, minimization, fullscreen, and mini-player mode. The `LibVLCSharp.WPF` package has been removed; the core `LibVLCSharp` wrapper remains for compatibility playback.

SRT and WebVTT files can stay on Windows playback for plain text, supported inline bold/italic/underline styling, supported foreground colors, and WebVTT background colors. First-party C# parsing and Windows/WPF text rendering support cue timing, multiline Unicode text, seeking, subtitle-track selection, and turning subtitles off. Balanced lowercase `<b>`, `<i>`, and `<u>` tags can be nested with supported color tags; their formatting is applied to the video overlay and native PNG snapshots. WebVTT also supports cue identifiers, comments, and its six named character references. SubRip supports common named text escapes and ordinary unescaped ampersands. Escaped markup remains literal text. A dedicated playback-clock timer updates captions, including consecutive cues with identical text but different styles or colors.

SubRip colors support lowercase `<font color="…">` tags with opaque `#RRGGBB` values or basic HTML color names (plus grey, cyan, magenta, and orange); values can be double-quoted, single-quoted, or unquoted. WebVTT supports its eight standard foreground classes: `<c.white>`, `<c.lime>`, `<c.cyan>`, `<c.red>`, `<c.yellow>`, `<c.magenta>`, `<c.blue>`, and `<c.black>`. The corresponding opaque background classes, such as `<c.bg_blue>`, also stay native. One foreground and one background class can share a tag in either order, for example `<c.yellow.bg_blue>`, following the [WebVTT default color classes](https://www.w3.org/TR/webvtt1/#default-classes). Nested tags restore the parent's foreground, background, and inline styles when they close. The renderer uses WPF's shaped glyph outlines, text selection geometry, and per-run brushes to keep overlay and snapshot colors consistent, including colored underlines, wrapped lines, and bidirectional Unicode text. Background fills stay inside the picture and clear when the cue changes or subtitles turn off.

WebVTT [voice spans](https://www.w3.org/TR/webvtt1/#webvtt-cue-voice-span) now also stay native. Speaker names in `<v Alice>Dialogue</v>` remain non-visible annotations, while dialogue, multiline Unicode text, inline styles, colors and backgrounds use the Windows/WPF renderer on both video and audio. A voice covering the whole cue may omit its closing `</v>`; other tags remain balanced. Standard foreground/background classes also work directly on supported bold, italic, underline and voice spans, such as `<b.yellow.bg_blue>Text</b>` and `<v.red Narrator>Text</v>`. The parser admits bounded plain speaker names and the same six named WebVTT character references. Automatic/manual loading, caption timing, backward seeks, subtitles-off, chapter commands, rotated source PNGs, restart and compatibility handoff retain the original caption files and track inventory.

WebVTT [language spans](https://www.w3.org/TR/webvtt1/#webvtt-cue-language-span), such as `<lang ja-JP>日本語</lang>`, also stay native for known Windows/.NET culture names. WPF's [per-range culture support](https://learn.microsoft.com/en-us/dotnet/api/system.windows.media.formattedtext.setculture) applies the language to text shaping, including language-specific Japanese/Chinese glyphs in the overlay and PNG snapshots. Neutral, script and region names are supported, including the documented `zh-CN` and `zh-TW` aliases. Nested language spans restore the surrounding language; styles, standard color classes and voice annotations retain their own scopes. Language annotations remain invisible, and changing only the language still refreshes the caption. Local and HTTP video/audio, subtitle selection/off, backward seeking, rotation, restart and later compatibility handoff preserve the original files and selected tracks.

SubRip's common [alignment extension](https://aegisub.org/docs/latest/ass_tags/#line-alignment), `{\an1}` through `{\an9}`, now stays native with Windows/WPF text alignment and layout. A single exact tag at the start of a cue selects bottom, middle or top placement, with left, center or right alignment. Multiline Unicode text, supported inline styles and colors retain their formatting, and an untagged cue returns to the usual bottom-center position. Captions stay upright and inside the fitted picture through resizing, mini-player, fullscreen, aspect overrides and rotation; source-resolution PNGs use the same placement. Automatic/manual loading, local and HTTP video/audio, seeking, selection/off, chapters, restart and compatibility handoff retain the original caption files and track selection.

Transparency, other color syntaxes, font face/size attributes, CSS (including voice/language-specific rules), custom WebVTT classes, competing or duplicate foreground/background classes, unknown or unsupported language tags, ruby, karaoke, WebVTT positioning, SubRip coordinate/movement/animation or combined overrides, overlapping cues, malformed or excessive markup, unusually long captions, and other unsupported subtitle content continue through VLC. ASS/SSA files retain their complete compatibility renderer. The parser retains the original files for compatibility handoff, so formatting is preserved when a later feature needs VLC.

Supported SRT and WebVTT sidecars are discovered beside the video and in its `subs` and `subtitles` folders, including supported inline styles. Both `.vtt` and `.webvtt` use the same strict UTF-8 WebVTT parser for automatic discovery and manual loading, including local and HTTP audio/video playback. The subtitle file picker includes both extensions.

A single exact-name sidecar (for example, `film.mp4` and `film.srt`) or a single qualified sidecar is selected automatically on Windows playback. Qualified names can describe a language, region, forced captions, or accessibility: `film.en.srt`, `film.pt-BR.vtt`, `film.en_US.srt`, `film.en.forced.webvtt`, `film_en.srt`, and `film (English SDH).vtt` are supported examples. The description must follow the complete media stem and a separator, using ASCII letters/digits, spaces, periods, underscores, hyphens, parentheses, or brackets. Multiple supported sidecars stay native when one exact-name file supplies an unambiguous default; all discovered tracks remain selectable. Discovery and parsing run away from the UI thread with limits on files, tracks, bytes, cues, and elapsed time.

Equal-priority defaults (such as two qualified files with no exact-name file), unsupported matching tracks, fuzzy names, non-ASCII or other unsupported descriptions, non-default search folders, and uncertain filename matching retain VLC's discovery and selection rules. Matching unsupported content in any track keeps compatibility playback instead of omitting that track. Restart and compatibility handoff preserve the complete native subtitle inventory, selected track or subtitles-off state, and original files. Restored native tracks populate the selector immediately, so automatic captions can be turned off and back on before the next metadata timer tick.

Supported external SRT/WebVTT captions now also stay native on audio-only sources, including direct HTTP/HTTPS audio with manually loaded captions. The first-party WPF renderer uses the full playback pane with an opaque black background; a previous video's last frame cannot show through. Automatic discovery, colors and inline styles, cue transitions, paused/backward seeking, audio disable/re-enable, chapter jumps, track selection, and subtitles-off work without creating a video stream or restarting the source. Audio-only snapshot requests and unsupported caption content retain the existing VLC fallback, including pause, position, audio selection, loaded caption files, and caption selection. Embedded captions outside the validated local MKV text path retain compatibility playback.

Discs, disc folders, other formats, and sources with unsupported embedded subtitles or alternate video streams continue through VLC. Caption discovery checks Windows' separate timed-text service as well as the audio/video stream inventory, so embedded captions do not disappear from the track selectors. RTSP/RTP/UDP streams, unidentified web content, unsupported web endpoints, and URLs with explicit username/password credentials also stay on VLC. Hardware decoding can be disabled for supported native video and audio; unavailable Windows software codecs retain compatibility playback.

Extensionless HTTP/HTTPS URLs and common download/API endpoints (`.php`, `.asp`, `.aspx`, `.ashx`, `.axd`, `.cgi`, `.bin`, and `.download`) can now keep supported MP4-family, WAV, AVI, Matroska, and ASF (WMV/WMA) content on Windows. Startup checks the content through the bounded range reader before admitting it: RIFF signatures and exact lengths must agree, MIME types must be compatible, MP4/Matroska files must pass the complete chapter/timeline inspection, and Windows must validate an ASF file's finite, seekable, unprotected timeline and canonical markers. The probe has a two-second network deadline, an 8 MiB traffic limit, and a 1 MiB cache. Identified types also travel to the Windows snapshot reader, so supported generic binary responses retain source-frame captures. The original source URL and query string stay in the session; the app does not add an extension or save a temporary media file. Playback still uses [Windows' source resolution](https://learn.microsoft.com/en-us/windows/win32/medfound/scheme-handlers-and-byte-stream-handlers).

These endpoint sources retain supported captions, chapter commands, snapshots, audio off/on, pause, rate, restart, and compatibility handoff. Matroska endpoints accept compatible audio/video Matroska MIME types or generic binary responses only after the full physical timeline has been validated, including chapters after the media data. Supported audio-only Matroska also retains multiple audio tracks and can run with hardware decoding disabled. ASF endpoints accept compatible WMV/WMA/ASF MIME types or generic binary responses after Windows' metadata reader validates the source. WMV retains source-frame snapshots and captions; WMA can also run with hardware decoding disabled. Validated Windows ASF markers remain available with VLC decoding, including when the Windows-playback preference is disabled. Handoff retains their provenance and reuses the map even if the server stops accepting ranges; opening a different container cannot carry those markers into the new session. Video with multiple audio tracks retains VLC because immediate seeking after a native track change did not reliably preserve the clock. Re-enabling the already selected native audio stream now changes mute state without unnecessarily reconfiguring that stream. Playlists/manifests, other EBML document types, non-range or live inputs, contradictory MIME types, uncertain RIFF/MP4 layouts, ordered/linked or other unsupported Matroska timelines, unvalidated ASF metadata, enabled visible chapter tracks, and other endpoint containers retain VLC. Recognized media-file URLs keep their existing format-specific routing and inspection.

Previous/next chapter navigation in supported local Matroska files now seeks through Windows Media Foundation without restarting playback. A bounded first-party EBML metadata reader admits a single visible edition with flat, enabled chapter markers on the physical timeline. It skips encoded media instead of decoding it and reads metadata away from the UI thread. Pause, playback rate, audio selection, loaded captions, and native snapshots remain available. Chapterless Matroska navigation stays native as a no-op, matching VLC. Native chapter commands wait off the UI thread for Windows to confirm each seek before calculating another jump, so rapid requests cannot both use the previous clock position. Explicit seeks reset the chapter-position hint. A confirmation timeout retains the intended absolute target during compatibility handoff.

Ordered, linked, nested, hidden/disabled, multiple-edition, malformed, or unsupported Matroska chapter metadata retains VLC from the start, so virtual timelines and chapter commands are not silently discarded.

Finite HTTP/HTTPS `.mkv` sources can now also stay on [Windows Media Foundation's Matroska support](https://learn.microsoft.com/en-us/windows/win32/medfound/mkv-support). Before native startup, the first-party reader validates the complete physical chapter timeline through bounded HTTP byte ranges, including chapters after the media data. Inspection runs off the UI thread with the same two-second network deadline, 8 MiB traffic limit, and 1 MiB cache used for HTTP MP4 chapters. It skips encoded media, validates HTTP responses and supplied entity validators, and saves no temporary media file. Supported audio-only sources retain multiple audio tracks and can run with hardware decoding off. Supported video with a single audio track retains chapters, caption selection, source-frame snapshots, pause/play, rate, and audio off. Chapterless sources keep chapter commands as native no-ops.

Failed or incomplete HTTP inspection, live/non-range sources, unsupported Matroska timelines, embedded subtitles, and unsupported codecs/streams retain VLC. Network Matroska video with multiple audio tracks also retains VLC: the native regression fixture could play and switch audio but could not confirm a subsequent seek. This restriction preserves seeking and track selection while that replacement remains incomplete. Restart and later compatibility handoff retain native caption files/selection, audio selection/off, pause, time, and rate.

Local MPG, MPEG, and standalone VOB program-stream files now try Windows playback when a bounded first-party metadata check finds a consistent program map with one video stream and at most one audio stream. The check reads at most 1 MiB without changing the source, validates map CRCs and packet bounds, and rejects private/DVD packets, scrambling, conditional access, extra or undeclared tracks, and unknown layouts. Windows' discovered stream counts must match the map before playback is accepted. Available Windows codecs still determine decoding; H.264/AAC and video-only fixtures are verified with hardware decoding enabled and disabled. Original-aspect resizing, pause/resume, rate and audio selection/off remain available. Validated chapterless files keep chapter navigation as a no-op.

MPEG seeking and frame capture still hand off to VLC: Windows accepted the regression fixture's seek but landed several seconds beyond the target, and its Source Reader shares this limitation. The handoff preserves position requests, pause, playback rate and audio-off; paused capture waits for a picture before pausing the compatibility input. MPEG files with automatic captions remain on VLC from startup, and manually loading captions switches to VLC before native caption presentation. This preserves existing caption behavior while first-frame/paused caption composition remains unverified. TS, MTS and M2TS files also retain VLC because caption restoration during native handoff could disturb their audio/video program inventory. Standalone VOB support does not alter DVD folder/disc navigation, protection or subpictures. No DVD/Blu-ray routing or compatibility libraries have changed.

Local MP4, M4V, M4A, MOV, and 3GP files also keep chapter navigation on Windows when their metadata contains a supported Nero version-1 chapter list, GoPro HiLight markers, or a supported QuickTime chapter track. A bounded first-party atom reader skips encoded audio/video and handles 64-bit box sizes and movie durations. Validated chapterless files keep navigation as a native no-op.

Direct HTTP/HTTPS sources in the same MP4 family now retain these supported chapter commands on Windows, including audio-only playback with hardware decoding off. Startup inspects chapter metadata away from the UI thread through the shared first-party HTTP range reader, with a two-second network deadline, at most 8 MiB fetched, and a 1 MiB cache. It skips media payloads and validates ranges, lengths, encodings, redirects, and supplied entity validators. No temporary media file is saved. Chapter jumps use [Windows Media Foundation seeking](https://learn.microsoft.com/en-us/windows/win32/api/mfmediaengine/nf-mfmediaengine-imfmediaengine-setcurrenttime) and preserve the native session, pause/play state, rate, audio selection/off, external captions, and video snapshots. Failed, slow, unsupported or inconsistent metadata inspection leaves the existing VLC chapter handoff available; enabled visible chapter tracks use compatibility playback from the start. Other unmigrated network containers and disc chapters retain compatibility playback.

QuickTime chapters support a single disabled, self-contained `text` or `tx3g` track on an unmodified timeline, including a single identity edit. The reader validates chapter ownership, timing, sample sizes, chunk mappings, local data references, and text-sample boundaries. It supports 32/64-bit headers and chunk offsets, fixed/variable sample sizes, multiple chunks, and run-length timing tables. Chapter jumps preserve the Windows session, paused/playing state, audio selection, external captions, and source-frame snapshots. Nero lists and GoPro HiLight markers retain their existing precedence when also present.

Enabled chapter tracks retain VLC from the start because they can also present visible text or pictures. Alternate chapter lists, external references, trims/gaps/rate changes, nonzero composition offsets, fragmented/compressed movies, oversized or malformed metadata, and other unsupported layouts retain VLC chapter navigation through the existing session handoff.

Local WMV, WMA, and ASF chapter markers now use Windows' metadata APIs, with chapter seeks through Media Foundation during native playback. The reader opens files with read-only access through `IWMMetadataEditor2` and retrieves markers through `IWMHeaderInfo`; it never flushes or edits the source. It validates a finite, seekable, unprotected timeline and distinct marker times, with limits on marker count, name size, and inspection time. Chapterless files keep navigation as a no-op. The [Windows marker API](https://learn.microsoft.com/en-us/windows/win32/wmformat/using-markers) supplies the canonical timeline instead of adding a bundled ASF parser.

Finite HTTP/HTTPS WMV, WMA, and ASF sources now also keep supported chapter navigation on Windows. The shared bounded range reader feeds Windows' [`IWMSyncReader::OpenStream`](https://learn.microsoft.com/en-us/windows/win32/wmformat/to-create-a-synchronous-reader-and-open-a-file), and `IWMHeaderInfo` supplies the same canonical markers and validation used for local sources. This reader is used only for metadata; playback and chapter seeks remain on Media Foundation. Inspection runs off the UI thread with a two-second network deadline, an 8 MiB traffic limit, and a 1 MiB cache. It requests no decoded samples, performs no metadata writes, and saves no temporary media file. Supported native video keeps source-frame snapshots and captions; supported WMA audio also retains native playback with hardware decoding disabled. Failed metadata inspection leaves basic playback available and retains the existing chapter handoff.

These Windows marker maps also remain available during local and supported HTTP ASF compatibility playback, including when complex captions need VLC, or when the Windows-playback preference is disabled. This adds chapter navigation where the bundled VLC ASF reader exposes no chapters. Handoff retains an already validated map without repeating metadata inspection, so marker navigation can continue if the server stops supporting ranges. Paused seek positions drive subsequent chapter commands, the timeline display, and resume bookmarks while VLC caches its old clock. Playback, explicit seeks, and source replacement update or clear that position. Native chapter jumps retain captions, audio off/selection, playback rate, paused state, and source-frame snapshots. Unreadable or unsupported marker metadata, duplicate times, excessive markers or names, and failed remote inspection retain the existing compatibility behavior.

Validated ASF video can also use Windows [Source Reader capture](https://learn.microsoft.com/en-us/windows/win32/medfound/processing-media-data-with-the-source-reader) while live playback remains on VLC. This includes original-aspect video with hardware decoding disabled or the Windows-playback preference off, using local files, supported HTTP sources, and identified download endpoints. Capture uses the confirmed physical chapter position after paused seeks, so it does not depend on VLC producing another picture. It preserves the player, pause/play state, audio selection/off, rate, source URL, and selected supported external SRT/WebVTT captions. Manually loaded and restored plain caption files are associated with uniquely confirmed VLC track IDs; the current selection supplies snapshot captions, and source replacement clears those associations. Caption files that have changed since parsing keep their compatibility renderer. Handoff publishes restored controls before dependent commands run, without waiting for a metadata timer tick. Manual rotation, forced aspect ratios, alternate or disabled video, unknown/automatic/embedded or complex caption tracks, and unvalidated timelines retain VLC capture. If Windows cannot read or decode the source, capture retries the existing renderer; an already failed native snapshot is not decoded a second time during the same handoff. VLC's video-output limitation after paused ASF seeks can still affect these remaining compatibility capture paths.

Unsupported embedded captions, complex external subtitle rendering, and unmigrated chapter navigation still use the compatibility backend. Requesting one of these features during native playback switches the current source to VLC, retaining its position, paused state, audio-track choice, rotation, and loaded SRT/WebVTT tracks (including supported styles and the subtitles-off selection) before applying the command. Captions are restored once during handoff without duplicate tracks. Audio and caption selections are confirmed before dependent commands run, including audio-off restoration when a native command is still completing. The saved position is applied after stream selection and pause restoration; paused seeks settle on the playback worker and retry once if VLC's input clock moves away from the target. Manually added compatibility captions are also explicitly selected after discovery. Snapshots that Windows cannot decode also retry through VLC. Hover over the playback status to see the active engine.

**Inspector → View → Aspect ratio → Original** preserves the source display aspect ratio as the window changes size, including mini-player and fullscreen. Windows handles native picture-aspect correction and letterboxing; VLC uses its automatic source aspect ratio.

VLC, the LibVLCSharp wrapper and AACS are retained dependencies. DVD and Blu-ray playback in the main player use the working VLC/AACS backend. The native disc replacement effort has stopped; the separate experimental readers and preview remain available as development code. Existing Windows playback for supported ordinary files remains enabled. The detailed migration inventory below records that work and its limitations, rather than a scheduled disc rewrite.

VLC updates ship with NOIR releases. Normal builds and publishes now select our tested custom VLC engine through `tools/vlc/DefaultRuntime.props`, retaining DVD, Blu-ray and AACS support. The previous runtime remains available in a runnable backup. Build and publish validate the disc components and regenerate the plug-in cache. A separate VLC desktop installation does not update NOIR's bundled engine.

The completion target is common video/audio playback plus DVD and Blu-ray video. Rare formats, unusual stream protocols, and obscure subtitle/layout variants are no longer migration milestones. Existing compatibility support remains available for them; expanding their native support will not hold up the main work.

Random/shuffle playback, still holds, subpaths, alternate angles, extension data and ambiguous chapter markers are retained or flagged, rather than converted into a misleading linear chapter map. Invalid playlists are reported individually with a nonzero exit status; reports never overwrite existing files. The tool compiles the same first-party readers as the app, with no VLC/AACS references. This completes the playlist metadata foundation, not the Blu-ray playback backend; disc commands still use the working compatibility path.

The first supplied Blu-ray metadata export passed inspection: 11 playlists referencing six stream names, including two equal-duration playlists with different chapter lists and a still-image playlist. Export hashes were verified before inspection. This validates real-disc metadata reading; video/audio decoding, menu behavior and protected playback still require separate verification.

Final verification covers the common-file and disc requirements above. Remove VLC/AACS and their packaging only when the corresponding required replacement passes those checks. Dependency removal is not conditional on migrating every rare format, but DVD/Blu-ray functionality must not be lost to remove a library.

The detailed compatibility inventory below records current fallback cases. Items outside the reduced completion target are deferred:

| Area | Replacement and verification still needed |
| --- | --- |
| Video presentation | Windows software MJPEG negotiation and unavailable or oversized presentation surfaces. Original-aspect playback, manual rotation, forced aspect ratios, and source-orientation/rotation snapshots are native through supported hardware or software playback. |
| Captions | Embedded captions outside validated plain SRT in local MKV, ASS/SSA and image subtitles, complex SRT/WebVTT layout/CSS/overlap/karaoke, unsupported language tags, and ambiguous or unmigrated automatic discovery. |
| Chapters | Complex Matroska editions/timelines, remaining MP4 chapter layouts and edits, network chapters outside supported MP4/Matroska/ASF byte-range sources, and disc chapter navigation. |
| Formats and streaming | Remaining containers/codecs and RTSP/RTP/UDP, live/unvalidated network Matroska and Matroska video with multiple audio tracks, unidentified content and other web endpoints/containers, multi-audio-track endpoint video, and credential-bearing URLs. |
| Optical discs | DVD menus/navigation, Blu-ray navigation and AACS/protected playback, including real discs and disc folders. Replacement support must be verified on physical and protected media. |
| Dependency retirement | Remove the core LibVLCSharp wrapper, VideoLAN runtime/plugins, and AACS/disc libraries, then update build/installer/license packaging after their feature replacements pass verification. |

NOIR bundles an open-source libaacs runtime for AACS integration. It does not bundle decryption keys or certificates.

When an AACS-protected Blu-ray is opened, NOIR uses the bundled 64-bit libaacs and libbluray modules. If the runtime is missing or damaged, NOIR reports `AACS REQUIRED` instead of remaining at `BUFFERING 0%`. A protected disc that does not begin playback within 35 seconds is stopped with an AACS-specific error rather than buffering indefinitely. Unprotected Blu-rays do not require a key database.

For protected media, place your legally obtained plaintext `KEYDB.cfg` at `%APPDATA%\aacs\KEYDB.cfg` using **Quick Settings → Blu-ray AACS → Open key folder**. **Download AACS keys** accepts either plaintext or a ZIP download and extracts and validates the database before installing it. If a ZIP archive has already been saved as `KEYDB.cfg`, NOIR repairs it automatically at startup and retains the archive as `KEYDB.cfg.backup`. Finding a valid file does not prove that it contains a matching key for a particular disc; NOIR reports an unlock failure when playback cannot begin. A different compatible 64-bit `libaacs.dll` can be selected in Quick Settings and is validated and applied after NOIR restarts. The VideoLAN libaacs project supplies no keys or certificates; key material must be configured for the disc in accordance with local law, or the disc must be played with licensed Blu-ray playback software. Binary provenance, source links, and licenses for the replaceable bundled libraries are documented in `src/NoirMediaPlayer/ThirdParty/Aacs/README.md`.
